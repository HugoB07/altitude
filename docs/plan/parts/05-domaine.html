05

Domain model & SQL schema

Data

This is the most expensive section to get wrong. A correct schema makes features easy; an approximate one charges you a workaround on every screen.

5.1 The five invariants

  1. Sums to zero. For any transaction, the lines sum to zero per currency. A currency exchange produces two balanced pairs linked by a technical FX account.
  2. Immutable ledger. A posted entry is never edited in place: it is reversed and a new one issued. The correction stays visible.
  3. Derived balances. No balance is stored as truth. daily_balances is a rebuildable cache; a full rebuild must reproduce exactly the same figures.
  4. Explicit currency. No amount exists without its currency. Two amounts in different currencies only combine through a dated, recorded rate.
  5. Tenant isolation. Every business row carries a non-null household_id, enforced by RLS.

5.3 Core tables — annotated DDL

-- ─── Structure: portfolio tree ─────────────────────────────────────────
CREATE TABLE portfolios (
  id            uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  household_id  uuid NOT NULL REFERENCES households(id) ON DELETE CASCADE,
  parent_id     uuid REFERENCES portfolios(id) ON DELETE RESTRICT,
  path          ltree NOT NULL,          -- 'home.children.lea' → subtrees in one query
  name          text  NOT NULL,
  kind          text  NOT NULL DEFAULT 'standard',  -- standard | child | company | project
  color         text,
  target_alloc  jsonb,                       -- target allocation, for rebalancing drift
  is_archived   boolean NOT NULL DEFAULT false,
  created_at    timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX ON portfolios USING gist (path);
CREATE UNIQUE INDEX ON portfolios (household_id, path);

-- ─── Accounts: one table for every asset and liability ─────────────────
CREATE TABLE accounts (
  id            uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  household_id  uuid NOT NULL REFERENCES households(id) ON DELETE CASCADE,
  portfolio_id  uuid NOT NULL REFERENCES portfolios(id),
  name          text NOT NULL,
  -- kind drives the valuation engine's behaviour:
  -- cash | securities | savings | life_insurance | retirement | crypto
  -- | real_estate | vehicle | collectible | private_equity | receivable
  -- | loan | credit_card | other_liability
  kind          text NOT NULL,
  subtype       text,          -- 'pea' | 'pea_pme' | 'cto' | 'per_in' | 'av_multi' | 'livret_a' …
  currency      char(3) NOT NULL,
  institution   text,
  -- IBAN / account number: encrypted at rest, only the last four in clear
  external_ref_enc  bytea,
  external_ref_last4 text,
  -- type-specific attributes, validated by a Zod schema in the application
  attributes    jsonb NOT NULL DEFAULT '{}',
  is_liability  boolean NOT NULL GENERATED ALWAYS AS (
                  kind IN ('loan','credit_card','other_liability')) STORED,
  opened_on     date,
  closed_on     date,
  created_at    timestamptz NOT NULL DEFAULT now()
);

-- ─── Ledger ────────────────────────────────────────────────────────────
CREATE TABLE transactions (
  id            uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  household_id  uuid NOT NULL,
  booked_on     date NOT NULL,        -- accounting date, timezone-free on purpose
  value_on      date,                    -- value date when it differs
  kind          text NOT NULL,        -- buy|sell|dividend|interest|fee|tax|deposit|
                                         -- withdrawal|transfer|fx|revaluation|split|adjustment
  description   text,
  counterparty  text,
  source        text NOT NULL DEFAULT 'manual',   -- manual|import|connector|rule
  import_batch_id uuid REFERENCES import_batches(id),
  external_id   text,                    -- provider identifier, for idempotency
  dedupe_hash   bytea,                   -- deduplication fingerprint (§8.5)
  reverses_id   uuid REFERENCES transactions(id),  -- reversal link
  created_by    uuid REFERENCES users(id),
  created_at    timestamptz NOT NULL DEFAULT now()
);
CREATE UNIQUE INDEX ON transactions (household_id, external_id)
  WHERE external_id IS NOT NULL;
CREATE INDEX ON transactions (household_id, booked_on DESC);

CREATE TABLE entries (
  id             bigserial PRIMARY KEY,
  transaction_id uuid NOT NULL REFERENCES transactions(id) ON DELETE CASCADE,
  household_id   uuid NOT NULL,
  account_id     uuid NOT NULL REFERENCES accounts(id),
  -- signed amount: + into the account, − out of it
  amount         numeric(28,10) NOT NULL,
  currency       char(3) NOT NULL,
  -- securities side: set only when the line moves a quantity
  instrument_id  uuid REFERENCES instruments(id),
  quantity       numeric(38,18),
  unit_price     numeric(24,12),
  -- conversion frozen at trade date, so the past is never recomputed
  fx_rate_to_base numeric(24,12),
  category_id    uuid REFERENCES categories(id),
  memo           text
);
CREATE INDEX ON entries (account_id, transaction_id);
CREATE INDEX ON entries (instrument_id) WHERE instrument_id IS NOT NULL;

-- The invariant, enforced by the database rather than the application:
CREATE FUNCTION assert_balanced() RETURNS trigger AS $$
BEGIN
  IF EXISTS (
    SELECT 1 FROM entries
     WHERE transaction_id = COALESCE(NEW.transaction_id, OLD.transaction_id)
     GROUP BY currency HAVING sum(amount) <> 0
  ) THEN
    RAISE EXCEPTION 'unbalanced transaction (%)',
      COALESCE(NEW.transaction_id, OLD.transaction_id);
  END IF;
  RETURN NULL;
END; $$ LANGUAGE plpgsql;

CREATE CONSTRAINT TRIGGER entries_balanced
  AFTER INSERT OR UPDATE OR DELETE ON entries
  DEFERRABLE INITIALLY DEFERRED
  FOR EACH ROW EXECUTE FUNCTION assert_balanced();
Decision — the trigger is DEFERRABLE INITIALLY DEFERRED

The check runs only at COMMIT, so a transaction's lines can be inserted one at a time. Without deferral the first line would always fail, being alone and therefore unbalanced. This is the detail that makes the invariant usable in practice.

5.4 Ownership: the table that unlocks households

CREATE TABLE owners (
  id            uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  household_id  uuid NOT NULL,
  kind          text NOT NULL,   -- person | child | company | trust | undivided
  display_name  text NOT NULL,
  birth_date    date,                -- majority → switches visibility rules
  user_id       uuid REFERENCES users(id),  -- NULL when the owner never logs in
  attributes    jsonb NOT NULL DEFAULT '{}'  -- company number, legal form, marital regime…
);

-- Dated share: handles gifts, changes of regime, a new shareholder joining
CREATE TABLE ownerships (
  id          uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  account_id  uuid NOT NULL REFERENCES accounts(id) ON DELETE CASCADE,
  owner_id    uuid NOT NULL REFERENCES owners(id),
  share       numeric(9,6) NOT NULL CHECK (share > 0 AND share <= 1),
  -- split ownership: useful for family real estate
  right_type  text NOT NULL DEFAULT 'full',   -- full | usufruct | bare
  valid_from  date NOT NULL DEFAULT '-infinity',
  valid_to    date NOT NULL DEFAULT 'infinity',
  -- forbids two overlapping shares for the same account/owner pair
  EXCLUDE USING gist (
    account_id WITH =, owner_id WITH =,
    daterange(valid_from, valid_to) WITH &&
  )
);

The shares of an account at a given date must sum to 1. That check lives in the application (a SQL constraint would make step-by-step editing impossible); it runs on save and in the altitude doctor command.

5.5 Market reference and exposure

CREATE TABLE instruments (
  id           uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  isin         char(12), ticker text, mic char(4),
  name         text NOT NULL,
  asset_class  text NOT NULL,   -- equity|etf|fund|bond|crypto|commodity|cash|derivative
  currency     char(3) NOT NULL,
  country      char(2),           -- domicile, which is NOT real exposure
  sector       text, ter numeric(6,4),
  is_custom    boolean NOT NULL DEFAULT false,  -- user-created (REIT shares, SCI units…)
  household_id uuid                             -- non-NULL only when is_custom
);
CREATE UNIQUE INDEX ON instruments (isin) WHERE isin IS NOT NULL AND NOT is_custom;

-- Quote series: large → partitioned by year
CREATE TABLE instrument_prices (
  instrument_id uuid NOT NULL REFERENCES instruments(id) ON DELETE CASCADE,
  as_of         date NOT NULL,
  close         numeric(24,12) NOT NULL,
  currency      char(3) NOT NULL,
  source        text NOT NULL,
  PRIMARY KEY (instrument_id, as_of)
) PARTITION BY RANGE (as_of);
CREATE INDEX ON instrument_prices USING brin (as_of);

-- ⚑ The table that feeds the Globe: ETF look-through
CREATE TABLE instrument_exposures (
  instrument_id uuid NOT NULL REFERENCES instruments(id) ON DELETE CASCADE,
  dimension     text NOT NULL,   -- country | region | sector | asset_class | currency
  key           text NOT NULL,   -- 'US' | 'FR' | 'Technology' …
  weight        numeric(9,6) NOT NULL CHECK (weight >= 0 AND weight <= 1),
  as_of         date NOT NULL,
  source        text NOT NULL,   -- 'community' | 'manual' | 'provider'
  PRIMARY KEY (instrument_id, dimension, key, as_of)
);

-- FX: European Central Bank as the reference source, free and official
CREATE TABLE fx_rates (
  base char(3) NOT NULL, quote char(3) NOT NULL,
  as_of date NOT NULL, rate numeric(24,12) NOT NULL, source text NOT NULL,
  PRIMARY KEY (base, quote, as_of)
);
The community exposure dataset

Fund compositions are not freely redistributable from most providers. Altitude therefore ships a community-maintained data/exposures/*.json set covering the ETFs most widely held in Europe (MSCI World, S&P 500, emerging markets, Europe, bond funds…), each with an as-of date and a cited source. Users can override any line. It is an excellent "first contribution" task, and it makes the Globe useful straight after installation.

5.6 Valuation cache

CREATE TABLE daily_balances (
  account_id  uuid NOT NULL REFERENCES accounts(id) ON DELETE CASCADE,
  as_of       date NOT NULL,
  -- cash balance plus market value of holdings, in the account's currency
  cash        numeric(28,10) NOT NULL DEFAULT 0,
  market_value numeric(28,10) NOT NULL DEFAULT 0,
  cost_basis  numeric(28,10) NOT NULL DEFAULT 0,
  currency    char(3) NOT NULL,
  base_value  numeric(28,10) NOT NULL,  -- converted to the household's base currency
  -- the day's flows: indispensable for TWR (§6.3)
  net_flow    numeric(28,10) NOT NULL DEFAULT 0,
  is_estimated boolean NOT NULL DEFAULT false,  -- carried-forward price / manual value
  PRIMARY KEY (account_id, as_of)
) PARTITION BY RANGE (as_of);

net_flow is the field everyone forgets and without which no correct performance figure is possible: it separates deposits and withdrawals from market-driven change.
