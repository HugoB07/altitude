Modèle de domaine & schéma SQL

Données

C'est la section la plus coûteuse à corriger plus tard. Un schéma juste rend les fonctionnalités faciles ; un schéma approximatif fait payer chaque écran par un contournement.

5.1 Les cinq invariants

  1. Somme nulle. Pour toute transaction, la somme des lignes est nulle par devise. Une opération de change produit deux paires équilibrées reliées par un compte technique de change.
  2. Journal immuable. Une écriture validée n'est jamais modifiée en place : on la contrepasse et on en émet une nouvelle. La correction reste tracée.
  3. Soldes dérivés. Aucun solde n'est stocké comme vérité. daily_balances est un cache reconstructible ; sa reconstruction complète doit redonner exactement les mêmes chiffres.
  4. Devise explicite. Aucun montant n'existe sans sa devise. Deux montants de devises différentes ne s'additionnent qu'à travers un taux daté et enregistré.
  5. Cloisonnement. Chaque ligne de données métier porte un household_id non nul, contrôlé par RLS.

5.3 Tables du cœur — DDL commenté

-- ─── Structure : arbre de portefeuilles ────────────────────────────────
CREATE TABLE portfolios (
  id            uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  household_id  uuid NOT NULL REFERENCES households(id) ON DELETE CASCADE,
  parent_id     uuid REFERENCES portfolios(id) ON DELETE RESTRICT,
  path          ltree NOT NULL,          -- 'foyer.enfants.lea' → sous-arbres en une requête
  name          text  NOT NULL,
  kind          text  NOT NULL DEFAULT 'standard',  -- standard | child | company | project
  color         text,
  target_alloc  jsonb,                       -- allocation cible pour l'écart de rééquilibrage
  is_archived   boolean NOT NULL DEFAULT false,
  created_at    timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX ON portfolios USING gist (path);
CREATE UNIQUE INDEX ON portfolios (household_id, path);

-- ─── Comptes : un seul type pour tous les actifs et passifs ────────────
CREATE TABLE accounts (
  id            uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  household_id  uuid NOT NULL REFERENCES households(id) ON DELETE CASCADE,
  portfolio_id  uuid NOT NULL REFERENCES portfolios(id),
  name          text NOT NULL,
  -- kind pilote le comportement du moteur de valorisation :
  -- cash | securities | savings | life_insurance | retirement | crypto
  -- | real_estate | vehicle | collectible | private_equity | receivable
  -- | loan | credit_card | other_liability
  kind          text NOT NULL,
  subtype       text,          -- 'pea' | 'pea_pme' | 'cto' | 'per_in' | 'av_multi' | 'livret_a' …
  currency      char(3) NOT NULL,
  institution   text,
  -- IBAN/numéro : chiffrés applicativement, seuls les 4 derniers en clair
  external_ref_enc  bytea,
  external_ref_last4 text,
  -- attributs propres au type, validés par un schéma Zod côté applicatif
  attributes    jsonb NOT NULL DEFAULT '{}',
  is_liability  boolean NOT NULL GENERATED ALWAYS AS (
                  kind IN ('loan','credit_card','other_liability')) STORED,
  opened_on     date,
  closed_on     date,
  created_at    timestamptz NOT NULL DEFAULT now()
);

-- ─── Grand livre ───────────────────────────────────────────────────────
CREATE TABLE transactions (
  id            uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  household_id  uuid NOT NULL,
  booked_on     date NOT NULL,        -- date comptable (sans fuseau : c'est volontaire)
  value_on      date,                    -- date de valeur si différente
  kind          text NOT NULL,        -- buy|sell|dividend|interest|fee|tax|deposit|
                                         -- withdrawal|transfer|fx|revaluation|split|adjustment
  description   text,
  counterparty  text,
  source        text NOT NULL DEFAULT 'manual',   -- manual|import|connector|rule
  import_batch_id uuid REFERENCES import_batches(id),
  external_id   text,                    -- identifiant du fournisseur, pour l'idempotence
  dedupe_hash   bytea,                   -- empreinte de déduplication (§8.5)
  reverses_id   uuid REFERENCES transactions(id),  -- contrepassation
  created_by    uuid REFERENCES users(id),
  created_at    timestamptz NOT NULL DEFAULT now()
);
CREATE UNIQUE INDEX ON transactions (household_id, external_id)
  WHERE external_id IS NOT NULL;
CREATE INDEX ON transactions (household_id, booked_on DESC);

CREATE TABLE entries (
  id             bigserial PRIMARY KEY,
  transaction_id uuid NOT NULL REFERENCES transactions(id) ON DELETE CASCADE,
  household_id   uuid NOT NULL,
  account_id     uuid NOT NULL REFERENCES accounts(id),
  -- montant signé : + entrant sur le compte, − sortant
  amount         numeric(28,10) NOT NULL,
  currency       char(3) NOT NULL,
  -- volet titres : renseigné seulement si la ligne bouge une quantité
  instrument_id  uuid REFERENCES instruments(id),
  quantity       numeric(38,18),
  unit_price     numeric(24,12),
  -- conversion figée à la date de l'opération, pour ne jamais recalculer le passé
  fx_rate_to_base numeric(24,12),
  category_id    uuid REFERENCES categories(id),
  memo           text
);
CREATE INDEX ON entries (account_id, transaction_id);
CREATE INDEX ON entries (instrument_id) WHERE instrument_id IS NOT NULL;

-- L'invariant, imposé par la base et non par l'application :
CREATE FUNCTION assert_balanced() RETURNS trigger AS $$
BEGIN
  IF EXISTS (
    SELECT 1 FROM entries
     WHERE transaction_id = COALESCE(NEW.transaction_id, OLD.transaction_id)
     GROUP BY currency HAVING sum(amount) <> 0
  ) THEN
    RAISE EXCEPTION 'transaction non équilibrée (%)',
      COALESCE(NEW.transaction_id, OLD.transaction_id);
  END IF;
  RETURN NULL;
END; $$ LANGUAGE plpgsql;

CREATE CONSTRAINT TRIGGER entries_balanced
  AFTER INSERT OR UPDATE OR DELETE ON entries
  DEFERRABLE INITIALLY DEFERRED
  FOR EACH ROW EXECUTE FUNCTION assert_balanced();
Décision — le déclencheur est DEFERRABLE INITIALLY DEFERRED

La vérification n'a lieu qu'au COMMIT : on peut donc insérer les lignes d'une transaction une par une. Sans ce mode, la première ligne échouerait toujours puisqu'elle est seule et déséquilibrée. C'est le détail qui rend l'invariant utilisable en pratique.

5.4 Propriété : la table qui débloque le foyer

CREATE TABLE owners (
  id            uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  household_id  uuid NOT NULL,
  kind          text NOT NULL,   -- person | child | company | trust | undivided
  display_name  text NOT NULL,
  birth_date    date,                -- majorité → bascule des règles de visibilité
  user_id       uuid REFERENCES users(id),  -- NULL si le propriétaire ne se connecte pas
  attributes    jsonb NOT NULL DEFAULT '{}'  -- SIREN, forme juridique, régime matrimonial…
);

-- Quote-part datée : gère la donation, le changement de régime, l'entrée d'un associé
CREATE TABLE ownerships (
  id          uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  account_id  uuid NOT NULL REFERENCES accounts(id) ON DELETE CASCADE,
  owner_id    uuid NOT NULL REFERENCES owners(id),
  share       numeric(9,6) NOT NULL CHECK (share > 0 AND share <= 1),
  -- démembrement : utile pour l'immobilier familial
  right_type  text NOT NULL DEFAULT 'full',   -- full | usufruct | bare
  valid_from  date NOT NULL DEFAULT '-infinity',
  valid_to    date NOT NULL DEFAULT 'infinity',
  -- interdit deux quotes-parts qui se chevauchent pour le même couple
  EXCLUDE USING gist (
    account_id WITH =, owner_id WITH =,
    daterange(valid_from, valid_to) WITH &&
  )
);

La somme des quotes-parts d'un compte à une date donnée doit valoir 1. Ce contrôle est applicatif (une contrainte SQL le rendrait impossible à éditer par étapes), vérifié à l'enregistrement et par une commande altitude doctor.

5.5 Référentiel marché et exposition

CREATE TABLE instruments (
  id           uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  isin         char(12), ticker text, mic char(4),
  name         text NOT NULL,
  asset_class  text NOT NULL,   -- equity|etf|fund|bond|crypto|commodity|cash|derivative
  currency     char(3) NOT NULL,
  country      char(2),           -- domiciliation, ≠ exposition réelle
  sector       text, ter numeric(6,4),
  is_custom    boolean NOT NULL DEFAULT false,  -- créé par l'utilisateur (SCPI, part de SCI…)
  household_id uuid                             -- non NULL seulement si is_custom
);
CREATE UNIQUE INDEX ON instruments (isin) WHERE isin IS NOT NULL AND NOT is_custom;

-- Séries de cotations : volumineuses → partitionnées par année
CREATE TABLE instrument_prices (
  instrument_id uuid NOT NULL REFERENCES instruments(id) ON DELETE CASCADE,
  as_of         date NOT NULL,
  close         numeric(24,12) NOT NULL,
  currency      char(3) NOT NULL,
  source        text NOT NULL,
  PRIMARY KEY (instrument_id, as_of)
) PARTITION BY RANGE (as_of);
CREATE INDEX ON instrument_prices USING brin (as_of);

-- ⚑ La table qui alimente le Globe : transparisation d'un ETF
CREATE TABLE instrument_exposures (
  instrument_id uuid NOT NULL REFERENCES instruments(id) ON DELETE CASCADE,
  dimension     text NOT NULL,   -- country | region | sector | asset_class | currency
  key           text NOT NULL,   -- 'US' | 'FR' | 'Technology' …
  weight        numeric(9,6) NOT NULL CHECK (weight >= 0 AND weight <= 1),
  as_of         date NOT NULL,
  source        text NOT NULL,   -- 'community' | 'manual' | 'provider'
  PRIMARY KEY (instrument_id, dimension, key, as_of)
);

-- Taux de change : source de référence BCE, gratuite et officielle
CREATE TABLE fx_rates (
  base char(3) NOT NULL, quote char(3) NOT NULL,
  as_of date NOT NULL, rate numeric(24,12) NOT NULL, source text NOT NULL,
  PRIMARY KEY (base, quote, as_of)
);
Le jeu de données communautaire d'expositions

Les compositions de fonds ne sont pas librement redistribuables chez la plupart des fournisseurs. Altitude embarque donc un fichier data/exposures/*.json maintenu par la communauté, couvrant les ETF les plus détenus en Europe (MSCI World, S&P 500, émergents, Europe, obligataires…), avec date d'arrêté et source citée. L'utilisateur peut surcharger n'importe quelle ligne. C'est un excellent « premier ticket » pour les contributeurs, et cela rend le Globe utile dès l'installation.

5.6 Cache de valorisation

CREATE TABLE daily_balances (
  account_id  uuid NOT NULL REFERENCES accounts(id) ON DELETE CASCADE,
  as_of       date NOT NULL,
  -- solde espèces + valorisation des titres, dans la devise du compte
  cash        numeric(28,10) NOT NULL DEFAULT 0,
  market_value numeric(28,10) NOT NULL DEFAULT 0,
  cost_basis  numeric(28,10) NOT NULL DEFAULT 0,
  currency    char(3) NOT NULL,
  base_value  numeric(28,10) NOT NULL,  -- converti dans la devise de référence du foyer
  -- flux du jour : indispensables au TWR (§6.3)
  net_flow    numeric(28,10) NOT NULL DEFAULT 0,
  is_estimated boolean NOT NULL DEFAULT false,  -- prix reporté / valeur manuelle
  PRIMARY KEY (account_id, as_of)
) PARTITION BY RANGE (as_of);

net_flow est le champ qu'on oublie systématiquement et sans lequel aucune performance correcte n'est calculable : il isole les apports et retraits de la variation due au marché.
