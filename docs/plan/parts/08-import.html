Import CSV / XLSX / OFX / CAMT

Ingestion

Puisque l'import remplace la synchronisation, il doit être excellent, pas correct. C'est le premier contact d'un utilisateur qui arrive avec 5 ans d'Excel : s'il échoue, il ne reviendra pas.

8.3 Les pièges francophones — à traiter dès le premier jour

Encodage CP1252 / ISO-8859-1« VIREMENT SÉPA » devient « VIREMENT SÃPA ».Détection par chardet + heuristique : si l'octet 0xE9 apparaît hors séquence UTF-8 valide, c'est du Latin-1. Prévisualisation avant validation.

8.4 Presets : un fichier, un test

Un preset est une donnée, pas du code. Ajouter une banque ne demande aucune compilation ni aucune connaissance du cœur — c'est ce qui rend la couverture extensible par la communauté.

// packages/importers/presets/fr/boursobank-compte.json
{
  "id": "fr.boursobank.compte",
  "label": "BoursoBank — compte courant (CSV)",
  "match": {
    "headerContains": ["dateOp", "dateVal", "label", "amount"],
    "delimiter": ";", "encoding": "utf-8"
  },
  "columns": {
    "bookedOn":    { "from": "dateOp",  "format": "yyyy-MM-dd" },
    "valueOn":     { "from": "dateVal", "format": "yyyy-MM-dd" },
    "description": { "from": "label" },
    "amount":      { "from": "amount", "decimal": ",", "thousands": " " },
    "currency":    { "const": "EUR" }
  },
  "transforms": [
    { "kind": "stripPrefix", "field": "description",
      "values": ["CARTE ", "VIR ", "PRLV "] },
    { "kind": "inferKind", "rules": [
        { "match": "^VIR(EMENT)? ", "kind": "transfer" },
        { "match": "INTERETS",      "kind": "interest" }
    ]}
  ],
  "fixtures": ["boursobank-compte.sample.csv"]   // jeu de test obligatoire
}

Cible v1 : BoursoBank, Crédit Agricole, BNP Paribas, Société Générale, LCL, Caisse d'Épargne, Fortuneo, Hello bank!, Revolut, N26, Trade Republic, Degiro, Bourse Direct, Saxo, Binance, Kraken, Coinbase — plus le format générique paramétrable. Chaque preset arrive avec un fichier d'exemple anonymisé et un test qui vérifie le résultat attendu.

8.5 Déduplication

Deux niveaux, parce qu'un seul ne suffit jamais :

  1. Exact — sha256(account_id ‖ booked_on ‖ amount ‖ currency ‖ normalize(label)). Rejet silencieux : c'est le cas du fichier réimporté deux fois, qui doit être totalement indolore.
  2. Approché — même compte, même montant, date à ±3 jours, similarité trigramme du libellé > 0,7. Ces cas ne sont jamais rejetés automatiquement : ils sont présentés côte à côte pour arbitrage (« garder les deux » / « fusionner » / « ignorer »), avec une case « appliquer à tous les cas similaires ».
Le cas qu'on rate systématiquement

Deux prélèvements identiques le même jour, même montant, même libellé — et parfaitement légitimes (deux abonnements identiques, deux retraits de 50 €). Un rejet automatique fait disparaître de l'argent réel et détruit la confiance. D'où la règle : seule l'empreinte exacte (qui inclut l'identifiant externe quand il existe) déduplique automatiquement ; tout le reste remonte à l'utilisateur.

8.6 Règles de catégorisation

Moteur déterministe, ordonné, entièrement inspectable — pas de modèle statistique en v1.

{ "priority": 10,
  "when": { "descriptionMatches": "(?i)carrefour|leclerc|intermarch",
            "amountBetween": ["-500", "0"] },
  "then": { "category": "alimentation", "tags": ["courses"] },
  "stopOnMatch": true }
  • Règles utilisateur d'abord, puis un jeu de règles communautaire par pays, versionné dans le dépôt.
  • Apprentissage explicite : recatégoriser une transaction propose « créer une règle pour tous les libellés semblables » — l'utilisateur reste maître, il n'y a pas de magie invisible.
  • Réappliquer les règles est une action manuelle, avec prévisualisation du nombre de lignes affectées.
  • Une éventuelle assistance par modèle de langage sera opt-in, locale, et jamais activée par défaut — envoyer ses libellés bancaires à une API tierce contredirait la promesse du produit.

8.7 Sécurité de l'import

VecteurContre-mesure
Injection de formule CSVÀ l'export, toute cellule commençant par = + - @ TAB CR est préfixée d'une apostrophe. Sinon, un libellé malveillant importé puis réexporté exécute une commande dans le tableur de l'utilisateur.
Bombe zip (XLSX)Plafonds durs : 50 Mo compressés, 500 Mo décompressés, 200 000 lignes, 1 000 colonnes. Lecture en flux, jamais en mémoire complète.
XXE / entités externesParseurs XML (OFX 2.x, CAMT) configurés sans résolution d'entité ni DTD externe. Test de non-régression dédié.
Épuisement mémoireTraitement en flux de bout en bout, insertion par lots de 1 000, limite mémoire du conteneur worker fixée dans le compose.
Contenu actif dans un XLSMLes macros ne sont jamais exécutées — ExcelJS lit les données, pas le VBA. Avertissement affiché à l'utilisateur.
Rétention des fichiers brutsConservés 30 jours par défaut (utile pour rejouer un import raté), purge automatique, suppression manuelle possible à tout moment.

8.8 Rollback

Chaque import crée un import_batch. Toutes les transactions issues du lot le référencent. L'annulation contrepasse ou supprime l'ensemble en une transaction SQL, puis déclenche le recalcul des soldes à partir de la date la plus ancienne concernée. Une annulation d'import ne doit jamais laisser un état intermédiaire — c'est un test d'intégration obligatoire, exécuté sur chaque preset.
