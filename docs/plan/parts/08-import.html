08

CSV / XLSX / OFX / CAMT import

Ingestion

Since import replaces synchronisation, it has to be excellent, not merely adequate. It is the first contact for a user arriving with five years of spreadsheets: if it fails, they do not come back.

8.1 Supported formats

8.3 French-language pitfalls — handle these on day one

PitfallSymptom if unhandledHandling
CP1252 / ISO-8859-1 encoding"VIREMENT SÉPA" becomes "VIREMENT SÃPA".Detection via chardet plus a heuristic: if byte 0xE9 appears outside a valid UTF-8 sequence, it is Latin-1. Preview before confirming.
Semicolon delimiterA single column, everything glued together.Count occurrences of ;, ,, \t and | across the first 20 lines; keep the one whose count is most stable.
Decimal comma1 234,56 read as 1 or NaN.Normalise: strip spaces (including non-breaking and thin), then treat the last separator as the decimal marker. Decide per column, not per row.
DD/MM/YYYY dates03/04/2025 read as 4 March.Decide across the whole column: if any value has a first group above 12, the order is settled. Otherwise ask — never guess silently.
Separate debit/credit columnsAll amounts positive, balance nonsensical.The mapping supports "two column" mode and applies the sign. Consistency check against the closing balance column when present.
Junk header rowsThe first six lines of a bank export are an identification block.Find the first row whose column count stays stable across five consecutive rows.
Truncated, noisy descriptionsDeduplication and categorisation both degrade.Normalise: uppercase, strip accents (unaccent), collapse long digit runs, remove dates embedded in the description.
Amounts in parentheses(45.00) read as positive.Anglo-Saxon accounting convention: parentheses mean negative. Common in broker exports.

8.4 Presets: one file, one test

A preset is data, not code. Adding a bank requires no compilation and no knowledge of the core — that is what makes coverage community-extensible.

// packages/importers/presets/fr/boursobank-current.json
{
  "id": "fr.boursobank.current",
  "label": "BoursoBank — current account (CSV)",
  "match": {
    "headerContains": ["dateOp", "dateVal", "label", "amount"],
    "delimiter": ";", "encoding": "utf-8"
  },
  "columns": {
    "bookedOn":    { "from": "dateOp",  "format": "yyyy-MM-dd" },
    "valueOn":     { "from": "dateVal", "format": "yyyy-MM-dd" },
    "description": { "from": "label" },
    "amount":      { "from": "amount", "decimal": ",", "thousands": " " },
    "currency":    { "const": "EUR" }
  },
  "transforms": [
    { "kind": "stripPrefix", "field": "description",
      "values": ["CARTE ", "VIR ", "PRLV "] },
    { "kind": "inferKind", "rules": [
        { "match": "^VIR(EMENT)? ", "kind": "transfer" },
        { "match": "INTERETS",      "kind": "interest" }
    ]}
  ],
  "fixtures": ["boursobank-current.sample.csv"]   // test fixture required
}

v1 target: BoursoBank, Crédit Agricole, BNP Paribas, Société Générale, LCL, Caisse d'Épargne, Fortuneo, Hello bank!, Revolut, N26, Trade Republic, Degiro, Bourse Direct, Saxo, Binance, Kraken, Coinbase — plus a configurable generic format. Every preset ships with an anonymised sample file and a test asserting the expected result.

8.5 Deduplication

Two levels, because one is never enough:

  1. Exact — sha256(account_id ‖ booked_on ‖ amount ‖ currency ‖ normalise(label)). Silently skipped: this is the case of a file imported twice, which must be completely painless.
  2. Fuzzy — same account, same amount, date within ±3 days, trigram similarity of the description above 0.7. These are never auto-rejected: they are shown side by side for a decision ("keep both" / "merge" / "skip"), with an "apply to all similar cases" checkbox.
The case everyone gets wrong

Two identical direct debits on the same day, same amount, same description — and both entirely legitimate (two identical subscriptions, two €50 withdrawals). Auto-rejecting makes real money disappear and destroys trust. Hence the rule: only the exact hash (which includes the external id where one exists) deduplicates automatically; everything else goes back to the user.

8.6 Categorisation rules

A deterministic, ordered, fully inspectable engine — no statistical model in v1.

{ "priority": 10,
  "when": { "descriptionMatches": "(?i)carrefour|leclerc|intermarch",
            "amountBetween": ["-500", "0"] },
  "then": { "category": "groceries", "tags": ["food"] },
  "stopOnMatch": true }
  • User rules first, then a community rule set per country, versioned in the repository.
  • Explicit learning: recategorising a transaction offers "create a rule for all similar descriptions" — the user stays in control, nothing happens invisibly.
  • Re-applying rules is a manual action, with a preview of how many rows would change.
  • Any future language-model assistance will be opt-in, local, and never on by default — sending bank descriptions to a third-party API would contradict the product's promise.

8.7 Import security

VectorCountermeasure
CSV formula injectionOn export, any cell starting with = + - @ TAB CR is prefixed with an apostrophe. Otherwise a malicious description, imported then re-exported, executes a command in the user's spreadsheet.
Zip bomb (XLSX)Hard caps: 50 MB compressed, 500 MB uncompressed, 200,000 rows, 1,000 columns. Streamed reading, never fully in memory.
XXE / external entitiesXML parsers (OFX 2.x, CAMT) configured with entity resolution and external DTDs disabled. Dedicated regression test.
Memory exhaustionEnd-to-end streaming, batched inserts of 1,000, worker container memory limit set in the compose file.
Active content in XLSMMacros are never executed — ExcelJS reads data, not VBA. The user is warned.
Raw file retentionKept 30 days by default (useful to replay a failed import), auto-purged, manually deletable at any time.

8.8 Rollback

Every import creates an import_batch. All transactions from the batch reference it. Undoing reverses or deletes the whole set in a single SQL transaction, then triggers a balance recompute from the earliest affected date. Undoing an import must never leave an intermediate state — that is a mandatory integration test, run against every preset.
