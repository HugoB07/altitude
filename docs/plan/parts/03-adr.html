03

Architecture decisions (ADRs)

Arch

Condensed ADR format: context → decision → consequence. To be stored in docs/adr/NNNN-title.md and changed by pull request, never silently.

ADR-001 — PostgreSQL as the only data dependency

Context
We need a transactional store, a job queue, a cache, light search and time series. The temptation is to stack Postgres + Redis + ClickHouse.
Decision
PostgreSQL 17 fills all four roles. Extensions enabled: pgcrypto, ltree, btree_gist, pg_trgm, unaccent. Redis stays possible but optional.
Consequence
The docker-compose.yml is four services. Backup is a single pg_dump: no risk of inconsistency between two stores. In exchange, the job queue tops out around a few thousand tasks per minute — far beyond a household's needs.
Revisit if
An instance exceeds roughly 500 active users or 50M quote rows.

ADR-002 — Double-entry ledger, derived positions

Context
A transfer from a brokerage account to a current account must not look like income; buying a security converts cash into quantity; a foreign dividend comes with fees and withholding tax.
Decision
A transaction carries N entries (lines); the lines sum to zero per currency. Positions and balances are derived from the ledger, never entered directly.
Consequence
A property-testable invariant. Cost: each entry takes more work in the UI — hidden behind "recipes" (buy, sell, dividend, transfer) that generate the lines.

ADR-003 — Owners are distinct from users

Context
A six-year-old owns a savings account but has no application login. A holding company owns a property but is not a person. A joint account belongs to two people 50/50.
Decision
Three separate notions: users (who logs in), owners (who owns — natural person, legal entity, child), ownerships (an owner's dated share of an account).
Consequence
Net worth can be sliced by owner, household, user or portfolio independently. Any asset total must state its consolidation basis — this is explicit in the API.

ADR-004 — Bank connectors: external, optional, off by default

Context
Accessing PSD2 bank APIs requires an AISP licence. An open-source project cannot ship its own aggregator credentials.
Decision
A stable Connector interface, implementations distributed separately, enabled by environment variable, with credentials supplied by the operator. No keys in the repository. Full analysis in §7.
Consequence
The core stays legally neutral and testable without network access. Configuring a connector is an explicit, documented step.

ADR-005 — Server Actions for internal mutations, Route Handlers for the API

Context
Next.js offers two server mechanisms; mixing them without a rule produces an unreadable codebase and authorisation gaps.
Decision
A clean boundary: app/api/v1/** (Route Handlers) is the versioned public contract, authenticated by API token, documented with OpenAPI. Server Actions are UI-triggered mutations, authenticated by session cookie. Both call the same packages/core/services layer — no business logic in either.
Consequence
Logic is testable without HTTP. The public API never drifts from the UI. Review rule: a Server Action longer than 20 lines is a design bug.

ADR-006 — Numeric precision: never a floating-point number

Context
0.1 + 0.2 !== 0.3 in IEEE-754. Across 10,000 transactions the drift becomes visible. A crypto quantity needs up to 18 decimals.
Decision
In the database: numeric(28,10) for amounts, numeric(38,18) for quantities, numeric(24,12) for prices and rates. In TypeScript: decimal.js. At JSON boundaries: strings, never number.
Consequence
A bespoke Money type wraps amount plus currency and makes adding two different currencies a compile error. SQL aggregates stay exact.

ADR-007 — Multi-tenant isolation: two barriers

Context
On a family instance, one query missing WHERE household_id = ? exposes another household's net worth. This is the number-one failure class in multi-tenant applications.
Decision
(1) Every query goes through a scopedDb(ctx) helper that injects the filter — direct access to the Drizzle client is forbidden by an ESLint rule. (2) PostgreSQL Row Level Security as defence in depth, via SET LOCAL app.current_household at the start of each transaction.
Consequence
An application bug alone cannot cause a leak. Cost: migrations must create the RLS policies, and the migration role must differ from the application role.

ADR-008 — Valued history: materialised daily snapshots

Context
Rendering ten years of net worth by replaying the ledger on every request cannot be kept under 200 ms.
Decision
A daily_balances table (account × day × currency), filled incrementally by a nightly job and invalidated from the earliest date any entry touches. Portfolio-level aggregates are computed on the fly from that table.
Consequence
Fast reads, and a full rebuild is one command (altitude recompute --from 2015-01-01). Any backdated change triggers a partial recompute — worth watching on large imports.
