2.1 Le problème que résout Altitude

Finary a prouvé qu'il existe une demande forte pour une vue unifiée du patrimoine — bancaire, boursier, crypto, immobilier — plutôt qu'un énième outil de budget. Ses limites structurelles ouvrent l'espace :

Limite constatéeConséquence pour l'utilisateurRéponse d'Altitude
Données chez un tiersL'intégralité du patrimoine, des IBAN et des positions transite et réside chez un prestataire.Auto-hébergement complet, base incluse. Aucun appel sortant hors fournisseurs explicitement configurés.
Modèle payant par paliersLes fonctionnalités d'analyse (allocation fine, performance) sont derrière un abonnement.Tout est inclus, sans limite d'actifs ni de comptes.
Couverture d'actifs figéeImpossible de modéliser une SCI, un pacte Dutreil, des parts de groupement forestier, une montre.Types de comptes extensibles + attributs JSONB validés par schéma, plugins d'actifs.
Mono-utilisateurUn couple gère mal l'indivision ; les comptes des enfants sont hors modèle.Foyer, propriétaires multiples, quotes-parts, portefeuilles enfants (§10).
Export limitéEffet de verrouillage : sortir ses données est pénible.Export intégral (JSON canonique + CSV par table) et import du même format. Objectif : réversibilité totale.
Boîte noire de calculOn ne sait pas si la performance affichée est un TWR, un TRI ou une variation brute.Méthode de calcul nommée, documentée, testée contre des références publiques (§6.3).

2.2 État de l'art open source — ce qu'on emprunte, ce qu'on évite

Aucun projet existant ne couvre à la fois le patrimoine et le multi-propriétaire et l'immobilier. Chacun apporte une leçon.

ProjetStack / licencePoint fort à emprunterLimite qui laisse la place
GhostfolioAngular + NestJS + Prisma + Postgres + Redis, AGPLLe concurrent le plus proche : suivi de portefeuille titres/crypto, dashboards soignés, self-host Docker.Centré titres : pas de partie double, immobilier et crédits marginaux, pas de foyer multi-propriétaires, import limité.
Firefly IIIPHP / Laravel, AGPLRéférence de la partie double grand public : règles, budgets, récurrences, multi-devises solide, API mûre.Orienté budget et trésorerie : pas de positions titres, pas de valorisation de marché, pas d'allocation.
Actual BudgetJS local-first, sync CRDT, MITModèle local-first et synchronisation chiffrée : excellente inspiration pour la confidentialité et l'offline.Enveloppes budgétaires uniquement, pas de patrimoine.
Sure fork communautaireRuby on Rails, AGPLFork communautaire de maybe-finance/maybe, archivé en juillet 2025 ; couvre budget + patrimoine, self-host Docker.Écosystème Rails (moins accessible à la communauté JS visée), agrégation historiquement dépendante d'un fournisseur payant.
KresusNode + woob, AGPLLe précédent français : agrégation bancaire auto-hébergée via scraping.Démontre justement la fragilité du scraping : casse à chaque refonte de site bancaire, friction 2FA. Voir §7.5.
Portfolio PerformanceJava desktop, GPLLa référence de calcul : TWR, TRI, Modified Dietz, gestion des lots. À utiliser comme oracle de test.Application de bureau mono-poste, courbe d'apprentissage forte, pas de web.
Beancount / hledgerTexte brut, double entréeRigueur du modèle : invariants, immuabilité, réversibilité. Inspire directement le schéma §5.Réservé aux utilisateurs techniques, aucune interface grand public.
Décision — positionnement

Altitude = la rigueur comptable de Firefly III + la valorisation de marché de Ghostfolio + l'exactitude de calcul de Portfolio Performance, dans une interface web moderne, avec deux ajouts qu'aucun ne propose : le foyer multi-propriétaires avec portefeuilles enfants et les enveloppes françaises (PEA, assurance-vie, PER) modélisées correctement.

2.4 Principes directeurs

PrincipeCe que ça implique concrètement dans le code
Tes données t'appartiennentExport intégral réimportable depuis le jour 1. Aucun champ calculé qui ne soit pas reconstructible. La suppression de compte purge réellement.
Hors-ligne par défautL'application est pleinement fonctionnelle sans accès Internet, hors rafraîchissement des cotations. Aucune police, aucun script, aucune icône chargés depuis un CDN tiers.
Exactitude avant éléganceUn chiffre faux est pire que pas de chiffre. Chaque agrégat porte sa méthode et sa date d'arrêté. Les valeurs estimées sont visuellement distinctes des valeurs constatées.
Le grand livre est immuableOn ne modifie pas une écriture passée : on la contrepasse. Le journal d'audit est en ajout seul. C'est ce qui rend un import annulable.
Extension sans forkTypes d'actifs, presets d'import, fournisseurs de prix et connecteurs sont des interfaces déclarées, pas des switch dans le cœur.
La saisie manuelle est un citoyen de première classeElle n'est pas le mode dégradé de la synchro : c'est le mode de référence. Elle doit être plus rapide qu'une ligne Excel.
