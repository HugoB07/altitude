Garde-fou UI

Un outil de patrimoine se lit, il ne se regarde pas. Règle de revue : aucun composant animé dans un écran de saisie ou de rapprochement. Les effets Magic UI vivent sur la page d'accueil, l'onboarding et le dashboard « vitrine ». Budget de performance : INP < 200 ms sur la page Transactions avec 50 000 lignes.

4.4 Backend — où mettre quoi

BesoinMécanismeRègle
Afficher une pageServer ComponentAppelle directement core/services. Aucun fetch vers sa propre API — c'est un aller-retour réseau inutile.
Créer / modifier depuis l'UIServer ActionValidation Zod → assertCan(ctx, 'transaction:create', accountId) → appel service → revalidateTag. 20 lignes maximum.
API pour scripts, mobile, agentsRoute Handler app/api/v1/**Jeton d'API porteur, portées (read:accounts, write:transactions), limitation de débit, OpenAPI généré depuis les schémas Zod.
Rappel d'un agrégateurRoute Handler app/api/webhooks/**Vérification de signature, journalisation brute avant traitement, idempotence par identifiant d'événement.
Progression longue duréeSSE via Route HandlerAvancement d'import et de synchro. Pas de WebSocket : trop d'infra pour le gain.
Travail lourdJob pg-bossTout ce qui dépasse 2 s ou touche le réseau externe. Une requête HTTP ne doit jamais attendre une API tierce.

4.5 Monorepo

# pnpm workspaces + Turborepo
altitude/
├─ apps/
│  ├─ web/                 # Next.js 15 — UI + Route Handlers + Server Actions
│  ├─ worker/              # Node — pg-boss, cron, aucune dépendance à Next
│  └─ docs/                # Fumadocs — documentation publique
├─ packages/
│  ├─ db/                  # schéma Drizzle, migrations SQL, seeds, RLS
│  ├─ core/                # domaine pur : grand livre, valorisation, perf, autorisation
│  ├─ importers/           # CSV/XLSX/OFX/QIF/CAMT + presets + jeux de test
│  ├─ connectors/          # interface Connector + implémentations optionnelles
│  ├─ market-data/         # fournisseurs de cotations et FX, cache, repli
│  ├─ ui/                  # shadcn + Magic UI + graphiques + jetons de design
│  └─ shared/              # types, Zod, Money/Decimal, erreurs, constantes
├─ tools/
│  ├─ cli/                 # altitude backup|restore|recompute|import|doctor
│  └─ fixtures/            # générateur de données de démonstration
├─ docker/                   # Dockerfile, compose, entrypoint, healthcheck
└─ docs/adr/                 # décisions d'architecture
Décision — packages/core ne dépend ni de Next, ni de React, ni de HTTP

C'est la règle qui garde le projet testable et durable : le domaine se teste en millisecondes avec Vitest, sans navigateur ni serveur. Elle est vérifiable automatiquement avec dependency-cruiser en CI. Si demain Next.js change de paradigme, on réécrit apps/web, pas la logique métier.

4.6 Briques transverses

Journalisation
pino en JSON, identifiant de corrélation par requête, rédaction automatique des montants, IBAN et jetons en niveau info.
Erreurs
Sentry auto-hébergeable ou GlitchTip, désactivé par défaut. Aucune donnée financière dans le contexte d'erreur.
Métriques
Point /api/health (liveness/readiness) + /metrics Prometheus optionnel, protégé par jeton.
Courriel
nodemailer + SMTP fourni par l'hébergeur. Gabarits React Email. Aucun envoi si SMTP non configuré (dégradation silencieuse, pas d'erreur).
Fichiers
Interface Storage à deux implémentations : disque local (défaut) et S3 compatible. Fichiers d'import conservés 30 jours par défaut, configurable.
Recherche
pg_trgm + unaccent sur libellés de transactions et noms d'instruments. Aucun moteur externe.
Chiffrement
AES-256-GCM applicatif pour les secrets de connecteurs, clé maître dans ALTITUDE_ENCRYPTION_KEY (secret Docker), chiffrement enveloppe avec clé par enregistrement. Voir §7.8.
